# Life Commander — Product Architecture

## Product

Life Commander — Personal Life Operating System

## Current implementation state

The repository contains a functional local-first web application. The original visual prototype has been extended with CRUD flows, persistence, localization, validation, project/task relationships, calendar controls, habit tracking, finance records, journal and routine flows, backup/import, responsive behavior and accessibility-oriented interaction handling.

The project is currently in total release QA. Commercial packaging and sales are deliberately deferred until the QA gate is closed.

## Data architecture

Persistence is currently implemented with localStorage for the structured application dataset and lightweight preferences. JSON export/import is a first-class backup mechanism.

Domain entities:
- Task
- CalendarEvent
- Habit
- Goal
- Project
- Note
- JournalEntry
- Routine
- FinanceTransaction

Relations:
- Projects -> Tasks
- Tasks -> CalendarEvents through dates/scheduling
- Habits -> completion history
- FinanceTransactions -> finance categories
- Notes -> Projects
- JournalEntries -> mood/tags/date
- Routines -> routine steps/runs

## Localization

Supported locales:
- en
- ru
- es
- de
- fr

Rules:
- User-facing navigation, forms, status messages and empty states use localization dictionaries/helpers.
- Dates and weekday/month labels use locale-aware formatting.
- Language switching re-renders the application.
- Validation and backup messages are localized.
- Accessibility labels and dynamic modal controls are localized where generated by the application.

## Privacy model

- Local-first.
- No mandatory login.
- No mandatory server.
- No required third-party analytics.
- User data stays in the local browser storage unless the user explicitly exports it.
- JSON export/import is available for user-controlled backup and recovery.

## Release QA gates

1. Functional / UX QA
2. Data integrity and relationship QA
3. Localization QA
4. Responsive QA
5. Accessibility QA
6. Persistence / recovery / offline QA
7. Production deployment verification
8. Commercial packaging
9. Sales / marketplace preparation

Commercial packaging starts only after the release QA gates above are verified.
